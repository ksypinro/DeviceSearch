Device Search Engine

How the app's own search turns what someone types into a ranked list of their devices. Every query runs through up to three phases. Each phase replaces the results on screen as soon as it finishes, so the list is useful from the first keystroke and gets better when the person submits.

    Data plane

    Keeping the index current

    Queries never wait for the index. Device changes build a new snapshot in the background and swap it in. A query in flight keeps the snapshot it started with.

    Your app

    Device events

    The device store sends snapshots of the home through DeviceEventBridge: adds, removals, renames, room moves, status, usage.

    IndexSync

    Coalesce and rebuild

    Name and room changes wait 250 ms for more changes, then every lexical structure is rebuilt. That takes 5–15 ms for 500 devices. Status and usage take a fast path with no rebuild.

    IndexSnapshot

    One immutable value

    Documents, vocabulary, inverted index, name and fuzzy indexes, facet bitsets and vectors. Each rebuild raises the generation number.

    SearchEngine (actor)

    Atomic swap

    The engine takes the new snapshot. Observers such as the Spotlight indexer and the App Shortcuts refresh hear about it.

    Embeddings stay warm

    The meaning plug-in caches vectors on disk, keyed by model version and knowledge-base version. A rebuild reuses cached vectors and only embeds devices that changed.

    Personal signals

    Usage priors are 0.7 × log(1 + uses) / log(1 + max uses) + 0.3 × favourite. A nickname is learned after the same device is picked three times for the same search. A reformulation (a new search within 5 s, with no tap in between) counts as a miss.

    Kill switches

    Feature flags turn off meaning, re-rank, query rewrite, streaming re-rank, personalisation, nicknames, Spotlight and voice independently. With everything off, instant search still works.

    Swift package

    Module layers

    Each layer depends only on the layers beneath it. The engine knows nothing about embeddings or language models: those arrive as plug-ins behind protocols, so each one can be switched off or replaced. Select a module to see what it usesand what uses it.
